# MajaGo 新功能全链路实施手册：LBS 短视频社群基础设施

**目标市场：** 印度（重点）、东南亚
**版本目标：** MajaGo V2.0 (LBS Community Core)
**日期：** 2026年1月26日

---

## 1. 战略与顶层设计 (CEO/产品经理)

### 1.1 战略定位：本地化内容与社交基础设施

MajaGo 的新功能旨在从一个泛娱乐短视频平台升级为**“本地生活短视频社群”**。通过将地理位置群组作为 APP 的基础设施，我们实现了用户、内容、社群的自动连接。

**核心价值主张：** **“所见即所得，所得即所聊”**——用户在 MajaGo 上看到的任何有 LBS 标记的短视频，都能立即在对应的本地社群中进行讨论和沉淀。

### 1.2 市场聚焦：印度与东南亚的必要性

印度拥有庞大的移动互联网用户基数和极高的社交活跃度，但其二三线城市网络环境复杂、语言多样。东南亚市场（印尼、越南等）同样具备高增长潜力。

| 市场特点 | 战略机会 | 实施挑战 |
| :--- | :--- | :--- |
| **印度**：28邦+8联属地，多语言，弱网环境 | 庞大的本地化内容需求，社群粘性高 | 行政区划复杂，多语言适配，高并发，数据本地化 |
| **东南亚**：高移动渗透率，偏好本地内容 | LBS 社交空白，易于形成本地生活服务生态 | 复杂的行政区划，多语言/文化差异 |

### 1.3 核心功能矩阵

| 功能点 | 描述 | 战略意义 |
| :--- | :--- | :--- |
| **自动 LBS 群组** | 新用户自动加入其所在邦/省的群聊。 | 降低社交冷启动门槛，确保用户归属感。 |
| **内容自动同步** | LBS 短视频自动同步到对应群聊。 | 将内容流量转化为社群沉淀，提升内容讨论价值。 |
| **评论区融合** | 视频评论与群聊发言在评论区互通。 | 消除内容与社交的壁垒，创造沉浸式互动体验。 |
| **群组发现** | Group 页增加 My Group/Nearby Group 筛选。 | 满足用户多群管理需求，引导用户发现更多本地兴趣群。 |

## 2. 产品功能实现细节 (产品经理/技术负责人)

### 2.1 LBS 群组划分与适配 (技术重点)

我们采用 **“AA1 优先，动态降级”** 的全球适配策略，重点解决印度市场的行政区划问题。

1.  **印度 AA1 映射**：将印度的 **28 个邦 (States) 和 8 个联邦属地 (Union Territories)** 统一映射为 MajaGo 的 LBS 群组层级。
2.  **城市国家降级**：对于新加坡、香港等城市国家，群组层级降级至 **Level 0 (国家/地区)**，避免群组范围过小。
3.  **群组命名**：群组名称采用本地化语言，并支持多语言切换显示。例如，印度马哈拉施特拉邦的群组，在印地语用户界面显示印地语名称，在英语用户界面显示“Maharashtra State Group”。

### 2.2 评论区融合逻辑 (产品/技术)

这是 MajaGo 的创新点，需要精确的逻辑定义：

| 互动类型 | 触发位置 | 判定结果 | 评论区展示 |
| :--- | :--- | :--- | :--- |
| **视频评论** | 短视频评论区 | 视为对视频的**直接评论** | 默认 Tab：普通评论 |
| **群聊发言** | LBS 自动群聊中引用该视频发言 | 视为对视频的**本地讨论** | 切换 Tab：本地群聊，以卡片形式展示 |

**技术实现要点：**

*   **数据结构**：评论表和群聊消息表需通过 `video_id` 关联。群聊消息在评论区展示时，需携带 `group_id` 和 `group_name` 字段。
*   **同步机制**：群聊中引用视频的发言，需通过异步机制（如 MQ）同步到评论服务，并打上 `source: group` 标签。

### 2.3 新用户自动入群流程

1.  **注册/首次登录**：获取用户 IP 地址。
2.  **IP 定位**：通过 IP 确定用户所在国家和 AA1/AA2 信息。
3.  **LBS 授权**：提示用户授权 LBS，若授权则使用精确坐标修正 AA1。
4.  **群组匹配**：根据 AA1 匹配群组。
    *   **IF** 群组存在：自动加入。
    *   **ELSE**：系统自动创建群组，并向用户发送“恭喜，您是本群第一位成员”的欢迎消息。

## 3. 技术实施与架构要求 (技术负责人)

### 3.1 高并发与弱网架构

1.  **异步消息队列 (MQ)**：
    *   **用途**：处理短视频发布后的 LBS 群组同步、用户入群通知、群聊消息推送等高并发任务。
    *   **要求**：确保视频发布主流程不被阻塞，群聊同步延迟控制在 3 秒以内。
2.  **弱网优化**：
    *   **视频流**：实现 ABR (Adaptive Bitrate) 自适应码率传输，支持 360p/480p/720p 自动切换。
    *   **群聊协议**：采用 MQTT 或优化的 WebSocket 协议，支持断线重连和消息去重。
3.  **数据本地化**：
    *   **要求**：在印度和东南亚部署本地 CDN 和缓存节点，确保用户数据和内容符合当地数据主权法规。

### 3.2 多语言与本地化

1.  **多语言数据库**：所有用户可见的文本（包括群组名称、系统提示）必须支持多语言存储和动态调用。
2.  **翻译服务集成**：集成第三方翻译 API（如 Google Translate 或本地化翻译服务），为群聊和评论提供**一键翻译**功能。

## 4. UI/UX 设计规范 (UI/UX 设计师)

### 4.1 新用户冷启动体验

1.  **首次入群提示**：新用户首次进入 Group 页面时，使用**全屏引导卡片**或**模态框**，突出显示“您已自动加入 [XX邦/省群]”，并配以本地化欢迎语。
2.  **地理位置授权**：在注册流程中，以清晰的文案解释 LBS 授权的目的（“为您连接本地社群”），提高授权率。

### 4.2 评论区融合 UI 规范

**核心原则：** 评论区必须清晰区分“视频评论”和“本地讨论”的来源。

1.  **评论抽屉设计**：
    *   采用**顶部双 Tab 切换**：“视频评论” (默认) 和 “本地讨论”。
    *   **“本地讨论” Tab**：展示来自 LBS 自动群聊中引用该视频的发言。
2.  **群聊卡片样式**：
    *   群聊发言在评论区以**卡片形式**展示，而非普通评论样式。
    *   卡片顶部显示**群组名称**（如：来自 **[Maharashtra State Group]** 的讨论），并使用醒目的颜色或图标区分。
    *   卡片底部设置**“进入群聊”**或**“查看更多”**按钮，点击后跳转至 Group 页面。

### 4.3 Group 页面导航优化

1.  **默认状态**：新用户（仅一个 LBS 群）Group 页面默认直接展示 LBS 群聊界面。
2.  **多群状态**：当用户加入第二个群聊后，Group 页面自动切换为**群聊列表**，顶部增加 **My Group** 和 **Nearby Group** 两个页签。
3.  **My Group (我的群聊)**：
    *   LBS 自动群聊默认置顶，并带有**“家乡群”**或**“官方本地群”**的特殊标签。
    *   提供手动取消置顶功能。
4.  **Nearby Group (附近群聊)**：
    *   展示基于用户当前位置或筛选位置推荐的 AA2（市/县）群聊或兴趣群。
